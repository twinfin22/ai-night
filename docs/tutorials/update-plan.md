# AI 야학 튜토리얼 업데이트 계획

**작성일:** 2026-09-29
**상태:** 구현·자동 검증·사용자 검수용 미리보기까지. 공개 배포는 사용자 검수 뒤에만 한다.

## 1. 목표와 확정 사항

4050 소상공인이 수업을 혼자 복습하다 막혔을 때 현재 단계의 문맥을 담아 질문을 보내고 학습을 이어갈 수 있게 한다. 기존 20일 커리큘럼·주소·색감·Astro 구조를 유지하며, 베타에서 확인한 안내 불일치와 진행 문제를 고친다.

- 단계 이동은 `이전 · 다음`만 사용한다. 단계별 상태 선택과 별도 체크박스는 만들지 않는다.
- 모든 단계의 `도움이 필요해요`는 접근 가능한 대화상자로 이메일·질문만 받는다.
- 수신자는 서버에서만 `hello@ai-night.study`로 고정한다.
- 마지막 화면에는 완료 기준 1–3개와 `결과를 확인하고 수업 완료` 버튼 하나만 둔다. 마지막 화면 도달만으로는 완료하지 않는다.
- 사업 정보와 회고 본문은 AI 앱에서 작성한다. 사이트 입력은 환경·실습 경로 선택과 문의 이메일·질문에 한정한다.

## 2. 문의 요청과 학습 진행

### 문의 폼

흐름은 `도움이 필요해요 → 이메일·질문 입력 → 보내기 → 접수 결과 → 같은 단계로 돌아가기`다.

- 현재 화면 위 대화상자로 열며 이름과 첨부파일은 요구하지 않는다.
- 답변 받을 이메일과 질문은 필수, 질문은 최대 2,000자다. 초과 입력을 즉시 알린다.
- Day, 단계 ID·제목, 선택 앱·OS, 실습 분기, 교재 버전을 자동 첨부하고 요약을 폼에 표시한다. 없는 선택값은 `미선택`으로 기록한다.
- 열 때 대상 단계를 고정하고, 닫았다가 다시 열면 현재 단계와 일치하는지 확인한다.
- 전송 중에는 중복 클릭을 막고 `보내는 중`을 표시한다. 실패해도 입력을 유지해 재시도할 수 있게 한다.
- 성공 문구는 `문의가 접수되었습니다. 입력한 이메일로 답변드립니다.`만 사용한다. 답변 완료·문제 해결로 표현하지 않는다.
- 닫으면 학습 위치를 유지하고 도움 버튼으로 초점을 돌린다. 이메일·질문 초안은 현재 페이지 메모리에만 두며 진도·분석 이벤트에 넣지 않는다.

### `/api/contact` 확장

- 기존 홈페이지 교육 문의의 요청 형식과 수신 설정은 유지한다.
- 튜토리얼 유형은 이메일·질문·수업 문맥을 받고 서버가 수신자를 지정한다. 클라이언트는 수신 주소를 바꿀 수 없다.
- 제목은 `[AI 야학 튜토리얼] Day N · 단계 제목`, Reply-To는 학습자가 입력한 이메일이다.
- 서버에서 필수값·길이·Day 범위·앱·OS 값을 검증한다.
- 발송 서비스가 요청을 수락한 경우에만 성공을 반환한다. 수신함 도착을 검증한 것처럼 표현하지 않는다.
- 발송 예외·시간 초과를 처리한다. 재시도는 같은 요청 식별자를 사용하고, 발송 서비스의 중복 방지 지원을 공식 문서로 확인한 뒤 적용한다.
- 별도 문의 DB, 티켓 화면, 자동 회신은 만들지 않는다. 운영자는 받은 메일에 직접 답장한다.

### 진도와 완료

- 단계 이동은 위치를 자동 저장한다. 문의 전송은 진도·완료 여부를 바꾸지 않는다.
- 마지막 화면에 완료 기준을 읽기 전용으로 보여 주고, 학습자가 버튼을 눌렀을 때만 완료로 저장한다.
- 기존 완료 기록은 보존한다. ID 변경은 대응표로 이전하며 기존 `d01-folder`는 선택 OS의 폴더 단계로 연결한다.
- 저장소 접근에 실패해도 수업은 계속 쓸 수 있고, 재접속 뒤 진도가 유지되지 않을 수 있음을 화면에 알린다.

## 3. 베타 피드백 콘텐츠·화면 수정

| 대상 | 구현 내용 | 완료 기준 |
|---|---|---|
| Day 1 시작 | 앱·OS 선택 뒤 시작 버튼, 두 항목 선택 안내 | 화면 순서와 키보드 순서 일치 |
| Day 1 작업 공간 | 앱별 진입 → 작업 폴더 연결 → 연습 파일 읽기 확인. 설치돼 있으면 확인 단계로 진행 | 폴더 생성과 앱의 파일 접근을 구분 |
| Day 2·11·20 지침 | Codex는 작업 폴더 `AGENTS.md`, Claude Cowork는 프로젝트 지침을 사용. Claude Code 안내·파일 경로와 혼용하지 않음 | 같은 경로에서 저장·갱신·새 작업 적용 확인 |
| Day 4 연결 | 컴퓨터와 실행 위치 명시. Drive 연결을 파일 요약용으로 먼저, 브라우저 확장은 별도 설명 | 휴대폰 안내·컴퓨터 실행 구분 |
| Day 7 자료 변환 | 사이트에서는 슬라이드·문서만 선택. 대상·원본·목적은 선택 형식에 맞춘 복사 요청문으로 AI 앱에서 정리 | 없는 입력칸을 요구하지 않고 제작까지 이어짐 |
| Day 5·15·19 예약 | 기능 확인 → 시험 실행 → 생성 승인 → 목록·다음 실행 확인 → 수정·중지 | 생성 전 시험, 중지 방법 확인 |
| 예약 미지원 | 수동 실행 요청문과 직접 설정하는 학습 일정 안내 | 수동 대안과 자동 예약 성공을 구분 |
| Day 10 공개 | 계정·자료 준비, 공개 범위 확인, 사용자 승인, 주소·QR 확인, 수정 방법 연결 | 중단해도 위치 보존, 미리보기는 공개 완료가 아님 |
| Day 19 지속 학습 | 채널 선택과 실제 학습 일정 중심 | 계속 볼 채널과 실행 가능한 일정 |
| 공통 도움말 | 설치·연결·예약·배포·음성 변환의 화면 차이·기능 제한·자료 부족 대처 | 단계 도움말 또는 문맥 첨부 문의 |

모바일은 `설명 → 참고 화면·프롬프트 → 복사·실행 도구 → 단계 이동` 순서다. 자료 없는 단계는 빈 패널을 숨기며 복사 성공·실패를 시각과 보조기술에 모두 알린다. 메뉴명·플랜 조건·스크린샷은 공식 자료와 접근 가능한 실제 화면을 확인한 경우에만 쓴다. 브라우저에서 Windows를 선택한 결과는 실제 Windows 앱 검증이 아니다.

## 4. 구현 순서와 검증

1. 문의 폼·API 구현 및 기존 교육 문의 호환성 확인.
2. 완료 확인·진도 이전·저장 실패 처리.
3. Day 1·2·11·20 작업 공간과 지침 경로 수정.
4. Day 4·5·7·10·15·19와 공통 도움말·모바일 배치 적용.
5. 독립 브라우저 세션으로 전 과정을 검수하고 사용자 검수용 미리보기 준비.

필수 검증:

- 문의: 정상 접수, 잘못된 이메일, 빈 질문, 2,000자 초과, 발송 실패·시간 초과·재시도·중복 클릭, 수신자·Reply-To.
- 문맥: 앱·OS·Day·분기가 현재 화면과 일치하고, 닫아도 단계·입력이 유지됨.
- 접근성: 키보드 열기·닫기·전송, 초점 복귀, 오류 알림, 390px·데스크톱·200% 확대.
- 진도: 기존 완료·앱·OS·공통 수업 위치 보존, ID 이전, 마지막 화면 자동 완료 없음.
- 콘텐츠: Day 7 양쪽 분기, 예약 미지원, Day 10 공개 중단·재개, Day 11·20 지침 일관성.
- 전체 흐름: 분리한 테스트 저장소·세션에서 Codex·Claude·모바일 각각 Day 1–20 단계 전체를 순회해 기록.
- 발송은 모의 응답으로 자동 검증한다. 실제 수신은 발송 환경과 사용자 승인을 확보한 뒤 별도 확인한다.
- 커밋된 파일만 있는 환경에서 빌드·참조 자산을 검사해 미추적 파일 의존을 제거한다.

## 5. 산출물과 판단 기준

산출물은 문의 기능, 수정된 수업·공통 화면, 자동·브라우저 검증 결과, 실제 앱별 검증 범위, 사용자 검수용 미리보기다. 외부 앱에서 수행하지 못한 실습과 확인하지 못한 환경은 `미검증`으로 명시한다.

이 계획, 기존 개편 계획, 저작 기준, 진도 이전표, 환경 검증표를 최신 결정에 맞춘다. 별도의 단계 상태 네 가지와 체크박스는 도입하지 않는다. 학습자는 필요한 순간에 질문을 보내고, 수업 끝의 버튼 한 번으로 결과 확인을 기록한다.
